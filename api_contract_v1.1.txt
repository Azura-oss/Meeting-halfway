二、全局约定
2.1 两套返回结构（V1.1 重要变更）
V1.0 要求所有云函数统一返回 code/msg/data，这与已经真机验收的 AI 接口冲突。V1.1 明确区分两类云函数，由前端 service 适配层统一收敛，页面代码不得重复判断不同格式。
（1）AI 云函数：asrRecognize、parseIntent
成功以 ok: true 为标志，失败以 ok: false 加稳定错误码返回，并统一携带 requestId 便于排查与日志关联。
AI 接口返回结构
// 成功{  "ok": true,  "text": "我们仨从双流机场、武侯祠出发，坐地铁，想找咖啡厅",  "audioDurationMs": 8200,  "requestId": "req_20261006_8f3c1a"}// 失败{  "ok": false,  "code": "ASR_TIMEOUT",  "message": "语音识别超时",  "retryable": true,  "requestId": null}
提示：AI 接口不返回 code/msg/data。前端 service 层需把 ok === false 转换为统一的业务异常抛出，页面对两类接口的异常处理方式保持一致。
（2）业务云函数：searchPOI、getRecommendations、getRoutes、getPlaceDetail、收藏、历史、埋点
继续使用 code/msg/data 三段式结构，失败时 data 为 null。
业务接口返回结构
{  "code": 0,              // 0: 成功；非 0: 失败（见 2.5）  "msg": "success",       // 失败时为可直接展示的提示语  "data": {},             // 业务数据体；失败时为 null  "requestId": "req_..."  // V1.1 新增：请求追踪 ID}
提示：requestId 为 V1.1 新增字段。前端需要在异常提示的日志中记录该值，方便与后端日志对齐排查。
2.2 前端适配层要求
新增 services/ 或 utils/api 层，统一封装 wx.cloud.callFunction 调用与两类返回结构的解析。
页面只调用 service 方法并接收已归一化的结果或异常，不得在页面中判断 ok 或 code。
service 层统一处理：网络失败、云函数抛错、ok === false、code !== 0、data 为 null 四类情况。
service 层统一注入 requestId 记录与毫秒级耗时统计，便于联调期定位问题。
适配层示意代码
// utils/api.js —— 适配层示意（田维护）const AI_FUNCTIONS = ['asrRecognize', 'parseIntent']async function call(name, payload) {  try {    const res = await wx.cloud.callFunction({      name, data: payload    })    const body = res.result || {}    if (AI_FUNCTIONS.includes(name)) {      if (body.ok !== true) {        const msg = body.message || '识别失败'        throw Object.assign(new Error(msg), {          code: body.code,          retryable: !!body.retryable,          requestId: body.requestId        })      }      return body    }    if (body.code !== 0) {      const msg = body.msg || '服务繁忙'      throw Object.assign(new Error(msg), {        code: body.code, requestId: body.requestId      })    }    return body.data  } catch (err) {    if (!err.code) err.code = 500    if (!err.message) err.message = '网络开小差了'    throw err  }}module.exports = { call }
2.3 鉴权约定
所有涉及个人数据的接口（收藏、历史、埋点）由后端通过 cloud.getWXContext().OPENID 识别用户身份。
前端不得传递 openid，也不得把 openid 写入本地缓存后回传。
后端取得 openid 为空时，返回 code 401、msg「登录状态已失效，请重新进入小程序」。
收藏写入必须以 openid + placeId 建立唯一约束并保证幂等，重复调用不产生重复记录。
2.4 语音链路
语音输入在文档中固定为以下四步链路，缺一不可：
语音输入链路
asrRecognize → parseIntent → searchPOI → getRecommendations  取文字        取结构化意图    校验出发地      出推荐结果
parseIntent 只输出地点名称，不输出坐标。前端必须逐个调用 searchPOI 换取合法 poiId 与经纬度后再请求推荐。
searchPOI 返回重名或多个候选、无法唯一匹配时，前端必须让用户手动选择，不得自行取第一条。
searchPOI 对某个出发地返回空列表时，前端提示「没有找到该地点，请重新输入」并回到输入态。
parseIntent 返回 missingFields 非空时，前端按缺项弹窗引导用户补充，不得继续请求推荐。
2.5 公共字段与错误约定
项目
V1.1 统一要求
坐标
统一注明 GCJ-02；字段固定使用 lat、lng（数值，保留 6 位小数以内）
距离
统一使用米，字段名以 Meters 结尾，如 distanceMeters、distanceToMidpointMeters
时间
路线耗时统一使用分钟，字段名以 Minutes 结尾；业务时间使用 ISO 8601，如 2026-10-06T14:30:00+08:00
出行方式
统一枚举 walking、driving、subway、bus，前端负责映射为「步行 / 自驾 / 地铁 / 公交」
出行策略
strategy 仅在全员 subway 时有效，取 least_transfer 或 least_stops，其余情况传 null 或不传
参与人标识
participantId 由前端生成：当前用户固定为 self，其余成员为 p1、p2、p3…；后端在所有响应中原样回传。参与人数上限为 6（含 self），与 PRD A2 一致
空值
无列表返回 []，无对象返回 null；不得混用空字符串；可选字段缺失时统一返回 null
错误
每个接口列出稳定错误码、用户提示、retryable 与 requestId
列表上限
getHistory 最多返回最近 50 条；getFavorites 单页最多返回 100 条。推荐接口 getRecommendations 的 departures 最多支持 6 人
敏感信息
openid 由云函数上下文取得；腾讯位置服务 Key、TokenHub Key 等不得传到前端或写入本文档

9.1 田（前端）的独立开发策略

9.2 高（后端）的验收策略
