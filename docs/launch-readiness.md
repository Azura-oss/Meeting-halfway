### 本地审查发现

- [x] 结果页原先没有把地铁策略传给 `getRoutes`；现已补齐，并用页面级测试覆盖最少换乘、最少站点和混合交通三种情况。
- [x] 推荐、路线和历史云函数原先允许单人请求；现已按当前产品范围统一为 2–6 人，并补充 Smoke 回归。
- [x] 已增加 `REQUIRE_REAL_MAP=true` 上线防护：缺 Key 或上游失败时返回 502；真实服务正常空结果不混入种子数据。开发环境仍可显式使用种子模式。
- [x] 推荐地点快照入库失败时改为整个请求失败，避免路线、详情和收藏后续因缺失 `placeId` 而 404。
- [x] 历史记录已限制快照最多 20 条和 512 KiB，非法 `searchedAt` 由服务端兜底，并完整返回 `midpointMode`。
- [x] 移除代码未使用的 `getLocation` / `scope.userLocation` 声明；保留地点详情页的 `wx.openLocation` 导航能力。
- [ ] `getRecommendations` 的参与人耗时仍是直线距离估算，且地铁策略目前不改变候选排序；尚未达到“真实路线公平性”验收标准。
- [ ] 腾讯公交路线接口没有原生“最少站点”策略；当前 `least_stops` 映射为 `LEAST_TIME`。上线前需决定改名为“时间最短”，或实现并验证自定义最少站点选路。
- [ ] `getPlaceDetail` 只读取推荐写入的快照，电话、评分和图片通常为空；需确认比赛版本是否接受基础详情，或接入真实 POI 详情数据源。
- [ ] V1.1 Word 接口文档仍残留 1–5 人、旧历史去重和旧 AI 状态等口径；当前实现以 PRD V2.1 与最新交接为准，正式联调后再统一修订文档。
- [ ] `reportEvent` 在接口清单中存在，但仓库没有对应云函数；需确认它是发布范围还是明确延期。
