1. 产品概述			
1.1 一句话定义			
「哪见」是一款多人聚会碰面点推荐小程序：输入每个人的出发地（限成都市域）、出行方式和想去的场所类型，系统算出对所有人都公平的碰面点并推荐周边场所。支持语音输入，一句话自动解析出全部条件。			
1.2 背景与目标			
●?产品目标：朋友多人聚会时"在哪碰面"需反复协商（谁离得远、坐什么交通工具、去吃什么）。现有方案无法同时平衡多出发地、多出行方式、场所偏好三个变量。本产品给出对所有人都公平的碰面地点推荐。			
●?比赛目标：入围分赛区决赛。评审重点：真实场景、完成度、AI 能力应用。			
●?硬性节点：作品须于 7.17–10.17 期间提交；9.25 前核心链路上线。			
1.3 目标用户			
所有有微信、在成都地区有见面需求的人（不限年龄职业）。			
地区口径：不限制用户本人身在何处，但出发地只能选择成都市域内的地点；任何城市的用户都可打开使用。			
2. 范围			
2.1 本期实现			
●?核心链路：出发地输入（手动 / 语音）→ 选择偏好 → 折中点推荐 → 场所详情。			
●?基础能力：收藏、历史记录（持久化）、微信静默登录。			
2.2 明确不做（本期）			
●?沿途推荐（路线页沿途 500m 候选场所，列未来升级方向）。			
●?评分 / 评价数 / 人均价格展示（需接入第三方开放平台数据，留作后续迭代）。			
●?跨城碰面。			
●?爬取任何第三方平台数据（合规红线，永久不做）。

4. 详细功能需求（EARS 原则）			
模块 A：出发信息输入			
A1（Ubiquitous）：系统应默认展示 2 个出发地输入框，第一个框固定标记为「我」，后续框按序号标记（2、3、…）。			
A2（Event-driven）：当用户点击「＋ 添加其他人的出发地」时，系统应新增 1 个输入框，上限 6 个；达到上限后按钮置灰。			
A3（Event-driven）：当用户键入关键词时，系统应调用腾讯位置服务地点搜索接口展示 POI 联想列表，搜索范围限定成都市域；用户须从联想结果中选定有效 POI 才能作为出发地。			
A4（State-driven）：当任一出发地输入框未选定有效 POI 时，「下一步」按钮应保持置灰状态，并在页面提示「还有 N 个出发地没有选定，请从联想列表中选择具体地点」；全部选定后方可点击。			
A5（Event-driven）：当用户按住「按住说话」按钮时，系统应进入录音中状态（显示波形与计时、支持上滑取消）；松手后进入识别中状态。			
A6（Event-driven）：当语音识别完成后，系统应展示识别出的文字（可编辑），并解析出人数、出发地、出行方式、场所偏好等字段；信息完整时提示「信息完整，可以点击下方进入下一步」。当用户对场所偏好表达「都行」「随便」等模糊语义时，系统应默认全选所有场所类型，不判为缺项。			
A7（Unwanted）：如果语音识别结果信息不完整（缺人数、出发地、出行方式或场所偏好），系统应展示「请重说，还缺 N 项，请补充」及缺失明细，提供「按住重说」控件，且「下一步」保持置灰。			
A8（Event-driven）：当用户在已手动填写出发地后使用语音，或已用语音后改用手动输入时，系统应弹出确认对话框提示切换会清空已有内容，由用户选择「取消」或「清空并切换」。			
A9（Ubiquitous）：出行方式支持步行 / 开车 / 地铁 / 公交，每人只能单选一种；用户想更换出行方式需回到「选择偏好」页重新选择。			
A10（Ubiquitous）：场所类型按六大类分组展示，支持多选：			
●?吃吃喝喝：中餐、西餐、快餐、咖啡厅、奶茶、甜品			
●?逛逛商场：商场、超市			
●?High 玩：酒吧、KTV、棋牌游戏、网吧、游乐场、洗浴推拿			
●?运动健身：网球、篮球、足球、溜冰、游泳、乒乓球、台球、羽毛球、滑雪、跆拳道、保龄球、健身房			
●?文娱活动：电影院、音乐厅、剧场			
●?City Walk：公园广场、景区、博物馆、美术馆、图书馆			
（技术任务：每个类型需映射腾讯位置服务 POI 类目，形成映射表。）			
模块 B：折中点推荐			
B1（Event-driven）：当用户提交出发信息且出行方式为步行/开车时，系统应计算使所有参与者到达耗时最接近的点作为折中点（最长到达耗时尽量短、各人耗时尽量均衡）。			
B2（Ubiquitous）：候选场所卡片应展示：名称、类型、营业时间、距折中点距离（人均距离）、距当前用户距离。			
B3（State-driven）：仅当所有人的出行方式都选择地铁时，结果页才展示地铁策略切换，提供「最少换乘」（展示换乘站附近场所）与「最少站点」（展示折中站前后各 3 站范围内场所）两种策略。			
B4（Event-driven）：当用户选定某候选场所时，系统应在结果页地图上展示：每位参与者的位置标注、该场所标注、以及每人从出发地到该场所的完整路线（沿实际道路，非两点直线）；同时只显示当前点选的那一家场所的路线，换点别家即切换。			
B5（Unwanted）：如果 1km 半径内无匹配场所，系统应自动展示 5km 范围内结果，并提示「1km 范围内没有，已为您展示 5km 范围内的选择」；若 5km 内仍无结果，则展示空态并提供「返回修改」入口。			
B6（Ubiquitous）：结果页采用「地图在上、列表在下」的布局，地图底部浮层展示碰面点信息与各人到达时间，列表支持滚动查看全部场所。			
模块 C：场所详情与跳转			
C1（Event-driven）：当用户点击结果页场所卡片时，系统应进入店铺详情页，展示：头图、店名、类型、营业时间、到达情况（距碰面点 / 距你 / 各人到达时间）、地址（可复制）、电话（可拨打）。			
C2（Event-driven）：当用户在详情页点击「去大众点评」时，系统应尝试跳转至大众点评小程序对应页面；若跳转失败或路径失效，则降级为跳转大众点评首页。			
C3（Ubiquitous）：系统不得爬取大众点评等第三方平台数据；场所基础信息以腾讯位置服务 POI 数据为准。			
模块 D：收藏与置顶			
D1（Event-driven）：结果页每个场所提供「置顶」与「收藏」两个独立按钮。点击「置顶」后，该场所在本次搜索结果列表中置顶。			
D2（Event-driven）：点击「收藏」后，该场所持久化保存到收藏页，且在本次搜索结果列表中置顶。			
D3（Ubiquitous）：本次搜索结果列表排序规则为：已置顶 > 已收藏 > 默认（算法原序）；已收藏的置顶优先级低于手动置顶。			
D4（State-driven）：置顶仅对本次搜索生效（不持久化）；收藏持久化，跨会话可见。			
D5（Ubiquitous）：收藏页以纯店铺列表展示（店名 + 类型 + 距折中点距离），不展示分组与来源信息；空态时展示引导文案与「去找碰面点」入口。			
模块 E：历史记录			
E1（Event-driven）：每次搜索完成后，系统应持久化保存一条历史记录，含出发地组合、时间、人数、出行方式、场所偏好、折中点、收藏数。			
E2（Event-driven）：当用户在历史记录页点击某条记录时，系统应回到该次搜索的结果页，并恢复该次搜索的置顶 / 收藏状态与列表排序。			
E3（State-driven）：历史记录按时间倒序展示；空态时展示引导文案；提供「清空」入口（清空全部历史）。			
5. 主流程			
三条路径：			
路径 1（手动输入）：首页手输出发地 → 下一步 → 选择偏好页（每人出行方式 + 场所类型）→ 开始推荐 → 结果页。			
路径 2（语音输入 · 信息完整）：首页按住说话 → 识别 → 信息完整 → 下一步 → 直接跳结果页（跳过选择偏好页）。			
路径 3（语音输入 · 信息不完整）：首页按住说话 → 识别 → 信息不完整 → 提示「请重说」+「按住重说」→ 重说至完整 → 下一步 → 结果页。			
手动输入与语音输入互斥，不能同时使用；跨模式操作弹窗确认。

7. 数据与技术口径			
项目	口径		
地图与 POI	腾讯位置服务（地点搜索、 POI 详情）；出发地限成都市域		
折中算法	步行 / 开车：到达时间均衡；地铁：双策略（最少换乘 / 最少站点）		
语音识别	小程序录音（ getRecorderManager ） + 云函数调腾讯云 ASR 「一句话识别」； LLM 解析人数 / 出发地 / 方式 / 场所偏好		
后端	微信云开发（云函数 + 云数据库）		
账号	微信静默登录（ openid ）标识身份，不强制索取头像昵称		
收藏 / 历史	持久化存云开发数据库，按 openid 隔离；收藏不设上限，历史保留最近 50 条（超出自动清理最旧）		
埋点	搜索发起、结果曝光、收藏、置顶、语音使用、历史点击		
			
8. 非功能需求			
●?合规：完成小程序备案（主体梁秀峰）；提供《隐私政策》说明位置信息、录音信息用途；位置授权被拒时可手动输入地点兜底；录音需声明 scope.record 权限用途。			
●?性能：推荐结果返回 ≤ 3 秒（含耗时均衡计算时 ≤ 5 秒），超时提示重试。			
●?可用性：所有空态有引导文案；无地铁场景自动隐藏地铁策略；语音识别失败提供「按住重说」兜底。			
9. 验收标准			
1.? 输入 2 个成都出发地 + 每人出行方式 + 中餐 → 地图标注折中点，展示候选列表（按排序规则），所有候选点在地图有标注，点选后显示每人到该场所的路线。			
2.? 3 人全部选择地铁 + 最少换乘 → 展示换乘站周边场所；切到最少站点 → 展示折中站前后各 3 站范围内场所。			
3.? 语音说「我们仨从双流机场、武侯祠出发，坐地铁，想找咖啡厅」→ 信息完整 → 下一步直接进结果页。			
4.? 语音只说「想找咖啡厅」→ 提示「请重说，还缺 3 项」+「按住重说」，「下一步」置灰。			
5.? 1km 无结果时自动展示 5km 结果并提示；5km 无结果显示空态 +「返回修改」。			
6.? 对某场所点「置顶」→ 本次列表置顶；点「收藏」→ 进收藏页且本次列表置顶（优先级低于置顶）；重新搜索后置顶重置、收藏保留。			
7.? 搜索完成后历史记录页新增一条；点击该条回到当时结果页。
